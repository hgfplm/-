0. 部署包内容与架构总览

目录/文件作用
web\门户站点（纯静态，无需运行环境），放 IIS 即用
web\authorized.json商业授权软件条目（手工维护）
scripts\软件清单.csv软件信息清单（管理后台自动维护，一般不用手工编辑）
scripts\Build-Catalog.ps1扫描安装包 + 读取清单 → 自动生成门户数据
scripts\更新软件目录.bat手动刷新门户数据（管理后台不可用时的备用方式）
scripts\启动管理界面.bat + Admin-Server.ps1 + admin.html可视化管理后台：浏览器上传软件、填写信息、一键上下架
employee-guide.txt员工使用指南（部署完直接发全员）

架构一句话：员工浏览器访问 Web 门户下载安装包（零客户端安装）； 所有安装包均为本地文件，通过管理后台上传（或手动放入目录）， 软件页面信息自动生成，不需要手工编辑任何页面文件。

日常添加软件（推荐用管理后台，全程不碰文件）：

步骤动作
① 打开管理后台服务器上双击「启动管理界面.bat」，浏览器打开提示的地址
② 上传拖入安装包 → 填名称/分类/说明 → 点「上传并登记」
③ 完成安装包自动保存、清单自动登记、门户自动刷新，员工立即可见
本文档以 D:\SoftLibrary 为部署根目录示例，请按实际环境替换。

1. 准备工作

  • 一台 Windows Server（建议 2016 及以上），已加入 AD 域
  • 磁盘空间：软件包建议预留 50–100GB
  • 可访问公网（直接或走代理）——自动下载官方安装包需要；若服务器不能出公网，可在一台能出网的 IT 工作机上运行自动更新脚本，目录指向服务器共享
  • （可选但建议）在 DNS 中为服务器创建好记名，如 soft.corp.local

2. 部署 IIS Web 门户

2.1 安装 IIS 角色

# 管理员 PowerShell
Install-WindowsFeature Web-Server -IncludeManagementTools

2.2 复制部署包并创建站点

# 把部署包解压到 D:\SoftLibrary，然后：
New-WebSite -Name "SoftLibrary" `
    -PhysicalPath "D:\SoftLibrary\web" `
    -Port 80 -HostHeader "soft.corp.local" `
    -ApplicationPool "DefaultAppPool"

暂时不想配域名就去掉 -HostHeader，直接用 IP 访问 http://<服务器IP>/。

2.3 验证

浏览器访问站点能看到软件库首页（当前显示的是授权软件占位条目，属正常）。

3. 配置 MIME 类型与下载支持

安装包文件类型默认可能被 IIS 拒绝下载，一次性配置：

$site = "IIS:\Sites\SoftLibrary"
".msi",".exe",".zip",".7z",".msix",".msixbundle" | ForEach-Object {
    $ext = $_
    if (-not (Get-WebConfigurationProperty -Filter "//staticContent/mimeMap[@fileExtension='$ext']" -PSPath $site -Name fileExtension -ErrorAction SilentlyContinue)) {
        Add-WebConfigurationProperty -Filter "//staticContent" -PSPath $site -Name "." -Value @{fileExtension="$ext"; mimeType="application/octet-stream"}
    }
}
# 移除请求筛选对 .exe 的拒绝（如有）
Remove-WebConfigurationProperty -Filter "//system.webServer/security/requestFiltering/fileExtensions[@fileExtension='.exe']" -PSPath $site -Name "." -ErrorAction SilentlyContinue

4. 初始化软件（首次上架）

4.1 启动管理后台

在服务器上双击 scripts\启动管理界面.bat（要局域网访问需右键"以管理员身份运行"）， 浏览器打开窗口提示的地址：

http://localhost:8080/admin?key=admin123     （本机）
http://<服务器IP>:8080/admin?key=admin123  （其他机器）
上线前必改：① Admin-Server.ps1 顶部的 $Key 默认值（访问密钥）； ② 防火墙中对 8080 端口限制来源（仅允许 IT 部门网段/自己的 IP）。
下载记录功能：员工在门户点击下载时，页面会把下载行为上报到管理后台（8080 端口）， 按来源 IP 记录到服务器根目录 download-log.csv（时间/IP/软件/文件）， 管理界面的「下载记录」区可查看并按 IP 或软件名筛选（Excel 可直接打开该 CSV 做统计）。 注意：需要下载记录时管理后台须保持运行（不开不记录，但不影响员工下载本身）； 且 8080 端口需对员工机器开放上报，防火墙建议允许内网访问 8080——管理页面由密钥保护，无密钥只能上报不能查看。

4.2 批量上传软件

在管理后台中逐个上传：拖入安装包 → 系统自动识别文件名里的目录名/版本号 → 补填软件名称、分类、说明 → 点「上传并登记」。上传完成后门户自动刷新， 列表实时显示每个软件的状态（已上架 / 缺安装包）。

安装包事先集中下载好（清单 CSV 里预置了各软件的官方"软件源地址"可作参考）， 然后一口气传完。

4.3 验证

  • 浏览器 Ctrl+F5 刷新门户，各软件卡片、分类、版本号、大小显示正常
  • 点几个下载按钮确认能正常下载

5. 日常添加 / 更新软件（都在管理后台操作）

你要做什么怎么做
新增软件管理后台拖入安装包 + 填表 → 「上传并登记」→ 员工立即可见
升级版本同上，上传新安装包到相同目录名（旧包保留，门户自动显示最新版）
下架软件管理后台点「下架」→ 安装包移入 deleted-soft\ 备份（不删除，可手工恢复）
改名称/分类/说明同一目录重新上传同名文件并填新信息即可覆盖
调整授权软件编辑 web\authorized.json → 双击「更新软件目录」
原理：门户数据 web\data.js 完全由脚本生成，永远不要手工编辑。 管理后台的上传动作 = 保存安装包到 web\soft\<目录>\ + 更新软件清单.csv + 自动刷新门户，三步一次完成。 服务器不需要访问公网，所有安装包均为本地上传。
商业授权软件安装包不要通过管理后台上传（上传即全员可下载）。 授权软件只在 web\authorized.json 维护条目，待第 7 步 AD 权限控制启用后再提供下载。

6. 上线检查清单

#检查项通过标准
1门户访问内网任一员工机浏览器打开首页正常
2搜索/分类搜索"Chrome"能过滤出对应卡片
3安装包下载点击下载按钮能正常下载 .msi/.exe
4管理后台上传一个测试软件 → Ctrl+F5 门户出现卡片 → 后台点下架 → 卡片消失
5密钥已修改Admin-Server.ps1 的 $Key 已改默认值，防火墙已限制 8080 来源
6授权软件隔离确认 web\soft\ 下没有授权软件安装包
7通知全员发出 employee-guide.txt

7. 后续：AD 权限控制（暂缓项）

当前阶段全员可见。后续需要控制授权软件下载时：

  1. 创建受限目录 D:\SoftLibrary\web\soft-auth\，放入授权软件安装包
  2. IIS 中对 /soft-auth 路径关闭匿名认证、启用 Windows 认证： 
    Set-WebConfigurationProperty -Filter "/system.webServer/security/authentication/anonymousAuthentication" `
    -Name enabled -Value $false -Location "SoftLibrary/soft-auth"
Set-WebConfigurationProperty -Filter "/system.webServer/security/authentication/windowsAuthentication" `
    -Name enabled -Value $true -Location "SoftLibrary/soft-auth"
  3. 安装 URL Rewrite 模块，按 AD 组限制访问（如仅 CORP\SoftAuth-Users 组）
  4. 下载审计：IIS 日志中按用户名统计 /soft-auth 的下载记录（LogParser 定期出报表）
  5. authorized.json 中授权软件条目的 file 改指向 soft-auth/... 路径

排障：下载 404.3 → MIME 类型没配（第 3 步）；页面上没显示软件 → 没双击 bat 或清单"目录"列与实际文件夹名不一致；自动更新下载失败 → 官网地址变更或网络/代理问题，看控制台报错。
